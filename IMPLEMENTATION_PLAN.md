- **(K0i-α data-attr-prefix collision, 2026-05-03)** SSR-render regex tests of the form `<div\b[^>]*data-foo[^>]*>` will silently match a parent or sibling carrying `data-foo-block` / `data-foo-bar` because `data-foo` is a prefix of those longer attribute names. Surfaced when `CheersGeoffCallout` had both `data-cheers-stat-block` (outer container) and `data-cheers-stat` (inner stat div) — the test for the inner div's class string matched the outer container instead. **Fix pattern:** anchor with `data-foo="` (the closing quote of the value) rather than `data-foo[^>]*` when the component has nested elements with prefix-overlapping markers. Carries forward to every later component slice; alternative is to pick attribute names that don't share prefixes (`data-cheers-stat` + `data-cheers-stats-wrap` rather than `data-cheers-stat` + `data-cheers-stat-block`).

- **(K0f validation pattern, 2026-05-03)** SvelteKit's `error(status, message)` helper THROWS an `HttpError` rather than returning a Response. The framework runtime catches and serializes that throw on real requests, but in vitest — where tests call `POST(event)` directly with a hand-rolled `RequestEvent` — the throw escapes and the test fails. **Decision:** validation errors return `json({error: '<code>'}, {status})` directly instead of throwing. Production behavior is identical from a client's perspective; tests stay framework-agnostic and don't need `.rejects` couplings. Pattern applies to every later route (`api/*`) — never `throw error()` for input validation; reserve throws for genuinely unexpected server errors that the framework runtime should catch + log.

- **(K0f server-side test seam pattern, 2026-05-03)** Routes import a small set of adapters from `$lib/server/` (`anthropic.ts`, `rateLimit.ts`, `contextProvider.ts`, `buildSystemPrompt.ts`, `broadsheetPrompt.ts`). Each adapter that wraps an external dependency exposes a `_setOverride(...)` test hook (prefixed `_` to signal "private but importable for tests"). `_setAnthropic(client | null | undefined)` and `_setContextProvider(provider | undefined)` let integration tests inject deterministic fakes without `vi.mock(...)` module-reset gymnastics. **Cheaper and safer than vi.mock** for shared adapters: tests share a single seam, override semantics are obvious (`undefined` = use real, `null` = simulate missing, value = inject fake), and the `_resetRateLimit()` test helper keeps bucket state isolated per test. Pattern carries forward to every later API slice.

- **(K0f rate-limit scope, 2026-05-03)** In-memory per-instance sliding-window limiter (`Map<key, {count, resetAt}>`, 10 req/min). Per-instance state means Vercel cold starts wipe limits and concurrent serverless instances don't coordinate — acceptable for MVP-tier abuse prevention. Swap to Upstash/Redis at scale (track in K2-era tooling). Key is `x-forwarded-for` if present, else `event.getClientAddress()`. The 429 response carries `retry-after` + `x-ratelimit-*` headers.
